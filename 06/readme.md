# Hack 組譯器 (Hack Assembler)

nand2tetris 第 6 章專案：把 Hack 組合語言（`.asm`）翻譯成 16 位元 Hack 機器碼（`.hack`）。

## 功能

- 支援 A 指令（`@value`、`@symbol`）與 C 指令（`dest=comp;jump`）
- 支援標籤符號 `(LABEL)`、預定義符號與變數符號
- 自動忽略空白行、縮排與註解（`//`）
- 輸出的 `.hack` 檔每行一個 16 位元二進位字串

## 使用方式

本專案以 C# 實作，原始碼為 `HackAssembler.cs`。

```
dotnet new console -n HackAssembler
# 用 HackAssembler.cs 取代自動產生的 Program.cs
cd HackAssembler
dotnet run -- ../Add.asm
```

執行後會在 `Add.asm` 同一目錄產生 `Add.hack`。

## 專案結構

| 模組 | 職責 |
|---|---|
| `Main` | 讀檔、控制兩輪流程、寫出 `.hack` |
| `Parser` | 清除註解與空白，判斷指令類型，拆出 dest / comp / jump / symbol |
| `Code` | 把 dest、comp、jump 助憶符轉成二進位欄位 |
| `SymbolTable` | 儲存符號與位址的對應 |

## 運作流程

**第一輪：建立符號表**

1. 載入預定義符號。
2. 逐行掃描，維護 ROM 位址計數器。
3. 遇到 `(LABEL)` 時，記錄 `LABEL → 下一條指令的位址`；標籤本身不佔位址、不產生機器碼。
4. 遇到 A 指令或 C 指令時，位址計數器 +1。

**第二輪：產生機器碼**

1. 再次掃描，跳過標籤行。
2. A 指令：
   - `@數字` 直接轉成 15 位元二進位。
   - `@符號` 先查符號表；找不到就視為變數，從 RAM[16] 開始依出現順序配置位址並加入符號表。
3. C 指令：組合成 `111 a c1c2c3c4c5c6 d1d2d3 j1j2j3`。
4. 每條指令輸出一行 16 位元字串。

## 指令格式

- A 指令：`0vvvvvvvvvvvvvvv`（15 位元數值）
- C 指令：`111accccccdddjjj`

## 錯誤處理

組譯器遇到下列情況應該回報錯誤並指出行號：

- 無法辨識的 comp / dest / jump 助憶符
- A 指令的數值超過 15 位元（大於 32767）
- 標籤重複定義
- 輸入檔不存在，或副檔名不是 `.asm`

## 注意事項

- `@符號` 的符號可能是標籤、預定義符號或變數，查表順序以符號表為準，不要把標籤當變數重新配置。
- 變數位址從 16 開始，依第一次出現的順序遞增。
- 輸出檔不要有多餘的空白行，行尾換行格式請與比對檔一致。

## 學習問答 (Q&A)

整理學習過程中提出的問題與簡短答案。

### Q1：什麼是組譯器？

把組合語言翻譯成機器碼的程式。CPU 只看得懂二進位（如 `1110110000010000`），組合語言用 `D=A`、`@2` 這種助憶符讓人類好讀寫，組譯器負責把它們轉回 0 和 1。

| | 組譯器 | 編譯器 |
|---|---|---|
| 輸入 | 組合語言 | 高階語言 |
| 輸出 | 機器碼 | 組合語言或機器碼 |
| 對應關係 | 幾乎一對一 | 一行對應多條指令 |
| 複雜度 | 低，主要是查表 | 高，需語法分析與最佳化 |

在 nand2tetris 的位置：Jack → 編譯器 → VM → VM translator → 組合語言 → **組譯器** → 機器碼。

### Q2：如何實作？

核心流程只有三步：

1. 讀每一行，丟掉註解與空白。
2. **第一輪**：記錄每個 `(標籤)` 對應的 ROM 位址。
3. **第二輪**：A 指令轉二進位，C 指令查表後拼接。

模組分工：`Parser`（拆解）、`Code`（查表）、`SymbolTable`（符號對照）、`Program`（兩輪流程）。完整程式見 `HackAssembler.cs`。

### Q3：概念太多看不懂，能簡化嗎？

組譯器就是「查字典 + 拼字串」，輸出永遠是一行 16 個 0 和 1，只有三種輸入：

| 類型 | 範例 | 做法 |
|---|---|---|
| A 指令 | `@5` | 把 5 轉成二進位並補滿 16 位，開頭一定是 `0` |
| C 指令 | `D=A` | 拆成 dest、comp、jump 各自查表，拼成 `111` + comp + dest + jump |
| 符號 | `@LOOP` | 先掃一遍記下標籤位置，再掃第二遍替換成數字 |

兩輪掃描的原因：`@LOOP` 可能出現在 `(LOOP)` 之前，所以要「先找答案，再抄答案」。

### Q4：C# 程式碼看不懂，能逐步說明嗎？

以 `D=A` 為例，追蹤程式如何處理：

| 步驟 | 程式碼 | 結果 |
|---|---|---|
| 清理 | `IndexOf("//")`、`Substring`、`Replace` | 去掉註解與空白，得到 `D=A` |
| 拆解 | `IndexOf('=')`、`Substring` | `Dest = "D"`、`Comp = "A"`、`Jump = "null"` |
| 查表 | `Dictionary<string,string>`、`TryGetValue` | comp = `0110000`、jump = `000` |
| dest | `s.Contains("D") ? "1" : "0"` | `"D"` → `010` |
| 拼接 | 字串用 `+` 相接 | `111` + `0110000` + `010` + `000` = `1110110000010000` |

A 指令轉換：`Convert.ToString(5, 2).PadLeft(16, '0')` → `0000000000000101`。

用到的 C# 語法：

- `Dictionary<string, string>`：字串對字串的字典，用來查表。
- `TryGetValue`：查到就取值，查不到回傳 `false`，用來偵測寫錯的指令。
- `條件 ? 甲 : 乙`：簡寫的 if。
- `foreach`：對每一行各做一次，兩輪掃描各用一個。
- `try / catch`：遇到錯誤指令時印出「第幾行錯誤」而不是直接當掉。
